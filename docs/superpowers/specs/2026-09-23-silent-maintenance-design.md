# 管理器静默磁盘维护设计

日期：2026-09-23
状态：已与用户确认的设计（brainstorming 产出）
范围：`collector/maintenance.py`、`manager.py`、相关测试与维护说明

## 1. 背景与目标

当前磁盘维护只在管理器「磁盘维护」页手动触发，并同时处理 `logs/`、
`output/` 和 `data/*.db`。用户要求改为管理器内部每天静默执行：

1. 每天 05:00 执行；管理器稍后启动时当天补跑一次。
2. 保留期继续使用 `maintenance.keep_days`，当前为 30 天。
3. 只删除 `logs/` 中超过保留期的轮转日志。
4. `output/YYYY-MM-DD/` 不盘点、不删除，完全退出维护范围。
5. 对存在 SQLite 空闲页的 `data/*.db` 执行 `VACUUM`，不删除业务数据。

## 2. 已确认的决策

| 决策点 | 结论 |
|---|---|
| 调度位置 | 管理器内部定时器，不新增 Windows 计划任务或第三方依赖 |
| 触发方式 | 复用 `ManagerUI._refresh()` 的 5 秒监控循环 |
| 触发时间 | 每天 05:00；使用当前本地时区 |
| 错过处理 | 当天 05:00 后启动管理器时补跑一次 |
| 同日去重 | 独立状态文件记录最近一次尝试日期，管理器重启后不重复执行 |
| 执行方式 | 复用 `_run_bg()`，不弹窗、不更新维护页状态，只写管理器日志 |
| 并发保护 | 与手动维护共用 `_maint_running`，后台任务运行期间不重复启动 |
| 日志范围 | 保留轮转归档白名单和 30 天保留期；活动 `.log` 永不删除 |
| 产物目录 | `output/` 从自动和手动维护逻辑中完全移除 |
| 数据库压缩 | 仅空闲页字节数大于 0 时执行 `VACUUM` |

## 3. 设计

### 3.1 到期判断

新增纯函数判断“今天是否已到 05:00 且尚未尝试”：

- 输入： aware 当前时间、上次尝试日期。
- 当前时间早于 05:00 → 不触发。
- 当前日期等于上次尝试日期 → 不触发。
- 其他情况 → 触发，包含管理器启动后的当天补跑。

`_refresh()` 在现有监控循环中调用该判断。触发时先取得
`_maint_running` 锁，再启动后台任务。

### 3.2 持久化状态

新增独立的 `maintenance_state.json`，只保存最近一次尝试日期。
沿用现有状态文件的原子写入方式：先写临时文件，再 `os.replace()`。

后台任务无论正常返回还是抛出异常，都在回调中记录当天日期：

- 正常返回：记录成功执行。
- 抛出异常：记录已尝试，写日志，但不在 5 秒后无限重试。
- 进程在回调前退出：状态未写入，管理器下次启动会补跑。

### 3.3 静默执行

自动维护调用现有 `_run_bg()`，使用独立完成回调：

- 不弹确认框或错误框。
- 不修改「磁盘维护」页状态和报告。
- 成功、部分数据库失败、整体异常均写入 `logs/manager.log`。
- 与手动维护共用 `_maint_running`，避免同时运行。

### 3.4 维护范围

`collector/maintenance.py` 收敛为两部分：

1. `prune_logs()`：只删除 `logs/` 顶层、匹配轮转后缀且超过保留期的文件。
2. `compact_databases()`：先读取空闲页；为 0 时跳过 `VACUUM`，大于 0 时压缩。

删除 `prune_output()` 及其调用、报告字段和测试。`run()`、`scan()` 不再接收
`output` 目录。管理器维护页、确认文案、配置注释和项目文档同步移除
`output/` 清理描述。

### 3.5 已发现问题的处理

- `output/` 部分删除失败会被吞掉：通过彻底移除 `output/` 维护操作解决。
- 可回收空间为 0 仍执行 `VACUUM`：通过零空闲页直接跳过解决。

## 4. 错误处理

- 单个数据库 `VACUUM` 失败仍记录错误并继续下一个数据库。
- 自动任务整体异常写入管理器日志，并记录当天已尝试，避免高频重试。
- 活动日志、非轮转文件和 `output/` 永远不在删除白名单内。
- 不新增通知、弹窗或配置项。

## 5. 测试计划

`tests/test_maintenance.py`：

- `output/YYYY-MM-DD/` 在 dry-run 和 apply 后均保持原样。
- 过期轮转日志仍被删除，活动日志和无关文件保留。
- 空闲页为 0 的数据库不执行 `VACUUM`。
- 空闲页大于 0 的数据库执行 `VACUUM` 且业务行数不变。

`tests/test_manager.py`：

- 05:00 前不触发，05:00 当拍触发。
- 05:00 后启动且当天未尝试时补跑。
- 当天已尝试、同日再次检查时不触发。
- 状态日期可持久化并恢复。

## 6. 不做的事项

- 不新增 Windows 计划任务。
- 不新增 APScheduler 任务或第三方依赖。
- 不让 `output/` 参与自动或手动维护。
- 不改变 `maintenance.keep_days = 30`。
- 不改动预测、导出、采集、看板和数据库业务数据。
