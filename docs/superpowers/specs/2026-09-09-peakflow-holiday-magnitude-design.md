# PeakFlow 量级预测纳入法定节假日/补班 — 设计文档

日期：2026-09-09
状态：待用户评审

## 1. 背景与动机

现有 30 天进线量预测（`peakflow/`）的每日量级只由「趋势 + 星期季节因子」决定：
`forecast_ratio` 对未来日期取 `sidx.get(d.weekday(), 0.0)`，即按星期几套历史平均档位。
国家规定法定节假日（休息）与补班（上班）会打破普通星期规律，但当前逻辑不认识它们：

- 2026-10-01（周四·国庆·三薪）会被按**普通周四**预测 —— 虚高约 25~30%；
- 2026-09-20（周日·补班）会被按**普通周日**预测 —— 低估（应接近工作日量级）；
- 2026-02-16（周一·春节·三薪）会被按**普通周一**预测 —— 大幅虚高。

### 数据核查（用仓库内实际数据验证业务假设）

数据可用范围有限：`data/在线各类用户.csv`、`热线各类用户.csv` 覆盖 2026-06-04 → 09-08（97 天）；
各 `data/*.db` 实时库自 2026-07-01 起。窗口内只有 **1 个落在工作日的法定节假日**
（端午 6/19 周五·三薪），**没有任何补班日样本**（2026 年补班均在 1/4、2/14、2/28、5/9、9/20、10/10，
前 4 个早于数据起点，后 2 个尚未发生）。

结论：

1. **法定节假日量级降低 —— 数据支持**：端午 2026-06-19（周五）实际进线在线 10,089
   vs 前后正常周五 13,343 / 14,132（约 −27~29%），热线 9,236 vs 14,456 / 13,440（约 −33%），
   基本跌到当周周末水平。方向与「节假日 → 周日（一周最低档）」的映射吻合。
2. **补班量级 ≈ 周一 —— 无法用现有数据验证**：无历史补班样本。方向合理（平日→周末衰减仅
   12~24%，补班日在工作日水平是自然的），但「恰好≈周一」按业务规则编码，待 2026-09-20
   补班实况回看校准。
3. **客户量总量无日波动**：存量客群 1278.8 万，变异系数 0.20%（设计文档 2026-09-03 已验证）。
   量级调整只作用于进线/转人工，**客户量总量不做任何调整**；但因各客户类型份额同经
   `forecast_ratio`，覆盖档位会在标记日把各类型客户量**重新分配**（实测单日最大约 4.4%，
   如 2026-09-25/10-02，10-01 约 3.7%、09-20 约 1.2%），总量经归一化严格守恒，
   与既有份额机制一致，不改变总体量级。

## 2. 目标与范围

**目标**：让未来 30 天预测在遇到法定节假日（休假/三薪）时量级走低、法定补班时量级回到工作日档，
并对齐现有「趋势 + 星期季节」机制，改动最小。

**范围内**：日期→星期档位的覆盖规则；节假日日历数据载体；总览 sheet 备注列；模型测试。

**范围外（明确不做）**：

- 不做客户量调整（存量客群恒定，见上）。
- 不做三薪/休假量级差异（三薪是**排班成本**概念，量级上二者同为休息日，档位相同）。
- 不引入回归/节假日档位建模（历史仅 97 天、1 个假日样本，无法可靠估计，纯过拟合）。
- 不改转人工占比、sigma 回测机制。

## 3. 方案设计

### 3.1 语义映射

按日历类型覆盖星期因子：

| 日历类型 | 含义 | 量级档位 |
|---|---|---|
| 法定休假 / 法定三薪 | 休息日 | 该日套**周日档**（一周最低） |
| 法定补班 | 上班日 | 该日套**周一档** |
| （无标记） | 普通日 | 自身星期档（现状不变） |

说明：

- 周末落点的休假日（如 2026-10-03 周六三薪、10-04 周日休假）也统一套周日档：
  周六会略低于普通周六，长假整体走低更一致，规则可预期。
- 2026 年补班多为周六（仅 2026-09-20 为周日），周一档 > 周末档 → 自动回升到工作日水平。
- 未被标记日期、日历缺年份（2027 未录入）→ 行为与现状**逐位一致**。

映射施加点：`forecast_ratio` 的星期因子查表。该函数同时被「客户量份额预测」
（`forecast_client_volumes`）与「咨询占比预测」（`point_forecast`/`backtest_sigma`）调用，
改一处即传导到各层。客户量各类型份额同经 `forecast_ratio`：覆盖档位会在标记日把各类型
客户量**重新分配**（总量经归一化严格守恒，实测单日最大约 4.4%，与既有份额机制一致，
不改变总体量级）。进线 = 客户量 × 占比，转人工 = 进线 × 固定占比，随占比同步调整；
sigma 区间基于同一点估计 ±σ 生成，自动跟随。

### 3.2 日历数据载体

新增 `data/节假日.csv`，UTF-8，两列带表头：

```
日期,类型
2026-01-01,法定三薪
2026-01-02,法定休假
...
```

- 用户逐年向文件追加行即可，**无需改代码**（2026 年 43 行原样粘贴；2027 后续补充）。
- 文件缺失 / 无法解析 / 类型不在已知集合 → 降级为空映射并静默跳过，预测行为与现状相同。
- 仅识别两种行为类：休息类（`法定休假`/`法定三薪` → 周日档）与上班类（`法定补班` → 周一档）；
  未知类型视为无标记。

### 3.3 落点与改动文件

| 文件 | 改动 |
|---|---|
| `peakflow/models.py` | 新增日期→类型查表 `_holiday_map()`（`functools.lru_cache`，读 `config.HOLIDAY_FILE`）与 `_day_band(sidx, d)`（按类型返回覆盖档位）；`forecast_ratio` 的 `sidx.get(d.weekday(), 0.0)` 改为经 `_day_band` 查表 |
| `peakflow/config.py` | 新增 `HOLIDAY_FILE = DATA_DIR / "节假日.csv"` |
| `peakflow/report.py` | 总览 sheet 新增「备注」列：该日为 法定休假/法定三薪/法定补班 时标注类型，否则留空（肉眼核对生效情况） |
| `data/节假日.csv` | 新增，含用户提供的 2026 全部日期 |
| `tests/test_peakflow_models.py` | 见 §5 验证 |

`peakflow/forecast.py`、`main.py` **零改动**。

## 4. 边界与错误处理

- 日历含已过去日期（2026-01-01 等）：`forecast_ratio` 只对传入的 `future_dates` 生效，
  历史训练不受影响；回测窗口（最近 14 天）内无节假日日，sigma 不变。
  若未来某次回测窗口恰好含节假日后，预测侧同样套档，与实际走低一致，MAPE 只可能改善或持平。
- 序列不足 21 天的降级路径（`len(s) < 21` 直接取末值）：无星期结构，节假日覆盖不生效 ——
  可接受（该路径本就不含星期季节项）。
- CSV 中日期格式非法：该行跳过；整文件解析失败：返回空映射（`print` 一行警告）。
- 节假日类型为休息类且该日本身是周日：周日→周日，无变化（正确）。
- 各渠道独立运行，日历为全局共享数据文件，两渠道行为一致。

## 5. 验证与成功标准

1. **单元测试**（`tests/test_peakflow_models.py` 新增）：
   - 构造含星期季节的合成序列，标记某未来周一为休假 → 预测值 ≈ 同序列的周日档（与不标记时
     的周一档显著不同，接近周日档）；
   - 标记某未来周六为补班 → 预测值接近周一档；
   - 未标记日期输出与无日历文件时**完全一致**；
   - 日历文件缺失 → 行为与现状一致（不抛错）。
2. **端到端**：用现成数据 + `data/节假日.csv`（2026 全年）实跑 `python -m peakflow.main`，
   人工核对总览「备注」列与量级：2026-09-20（周日补班）回升至工作日档、
   2026-09-25~27（中秋）与 2026-10-01~07（国庆）走低至周日档。
3. **回归**：现有测试套件全绿。

## 6. 风险与已知局限

- **补班≈周一无可验证样本**（仓库内无历史补班实际值）——按业务规则编码；2026-09-20
  实况出现后回看，若偏离大再调（把补班档位换成其他工作日档或加系数）。
- 春节等长假若落在 30 天视窗之外（如 2027-01 春节），需运行时段恰好覆盖才能生效；
  长假中间日的实际深度可能超过周日档，届时据实校准。
- 年份维护依赖人工逐年补日历行；漏补年份的节假日不会自动识别（回到旧行为），
  属预期内降级而非错误。
